Dos frentes de trabajo

El equipo de ML trabaja en paralelo en dos lugares con el mismo objetivo: uno para experimentar rápido, otro con lo ya validado y corriendo en producción.

Notebook — experimentación

guias_ml/telemetria_colab.ipynb

Corre local en VS Code (Jupyter) o en Google Colab, sin obligación de mantenerse igual al código del proyecto. Acá se prueban ideas nuevas con datos reales.

  • EDA, features nuevas, otros algoritmos de clustering
  • Cuando algo queda validado, se decide qué y cómo portarlo (no es copy-paste literal)
machine_learning — producción

machine_learning/

Lo que corre 24/7 dentro de Docker Compose (servicio machine). Es la única fuente de verdad de lo que el resto del sistema consume.

  • Reentrena cada TELEMETRY_MODEL_INTERVAL_SECONDS (30s por defecto)
  • Expone /health con el estado del último entrenamiento

Pasos en detalle — código real

Lo que corre hoy en machine_learning/, tal cual está en el repo.

4·5

Limpieza + features → matriz lista para modelos

machine_learning/features.py

Orquesta 5 pasos en orden: limpia velocidades fuera de rango, imputa nulos con la mediana del lote, deriva hora_dia y exceso_velocidad, hace one-hot de event_name y estandariza (z-score) las columnas numéricas.

def build_dataset(rows, categorical_column="event_name"):
    rows = clean_rows(rows)
    rows = impute_missing(rows)
    rows = derive_features(rows)
    rows, category_columns = encode_categorical(rows, categorical_column)
    rows = scale_numeric(rows, list(NUMERIC_FEATURES))
    return rows, list(NUMERIC_FEATURES) + category_columns
Este módulo todavía no está conectado a telemetry.py/worker.py — el DBSCAN de zonas sigue usando lat/lon sin escalar (la métrica haversine necesita radianes reales, no valores estandarizados).

Despliegue — worker en loop

machine_learning/worker.py

Hilo en background que reentrena cada TELEMETRY_MODEL_INTERVAL_SECONDS (30s por defecto), pero solo si el cursor del ETL avanzó desde el ciclo anterior. Expone GET /health con el estado del último entrenamiento.

Cómo reproducirlo localmente

Setup completo (Docker, Mongo, .env) en el README.md de la raíz. Acá, el resumen enfocado en el modelo:

  1. Levantar todo con docker compose up --detach --build --wait Construye también la imagen de machine (tarda más la primera vez por las dependencias de ML).
  2. Confirmar que el servicio está sano: docker compose ps y curl localhost:<puerto>/health del servicio machine Debe responder status: "ok" con la versión de dataset entrenada.
  3. Ver logs del reentrenamiento en vivo: docker compose logs machine --tail 30 -f Imprime Machine: N zonas detectadas de M reportes (X% cobertura) en cada ciclo.
  4. Correr el notebook de experimentación: guias_ml/telemetria_colab.ipynb Kernel Jupyter/ipykernel local, o subirlo a Google Colab sin cambios (usa files.upload() en vez de leer CSV local).
  5. Correr los tests: python3 -m unittest discover -s tests -v Incluye tests/test_telemetry_model.py, específico del modelo.
